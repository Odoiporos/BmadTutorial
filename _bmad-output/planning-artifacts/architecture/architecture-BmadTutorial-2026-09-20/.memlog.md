- (version) Microsoft sources checked 2026-09-20: .NET 10 is the current LTS, SDK 10.0.401 is current, and the built-in console template targets net10.0 by default.
- (question) Choose the design paradigm and boundary strength after comparing simple layered architecture with ports-and-adapters.
- (decision) AD-1 will bind all capabilities to ports and adapters: core policy owns expense rules and use cases; console and JSON are replaceable adapters; dependencies point inward to the core, preventing UI and filesystem concerns from becoming domain logic.
- (decision) AD-2 will bind the solution to three projects: ExpenseTracker.Core, ExpenseTracker.ConsoleApp, and ExpenseTracker.Tests; the JSON adapter stays with the console host, preventing project-per-concept ceremony while keeping the inward dependency explicit.
- (decision) AD-3 will make one core ExpenseTracker service the exclusive owner of the in-memory collection; commands cannot mutate it directly, and load replaces state only after full validation, preventing competing mutation paths and partial replacement.
- (decision) AD-4 will use explicit operation results for expected validation and storage failures; adapters translate technical failures to user-safe messages, while exceptions remain for unexpected faults, preventing inconsistent error handling and accidental termination.
- (version) xUnit official sources checked 2026-09-20: xUnit.net v3 4.0.1 is current stable; the v2 line is maintenance-only; v3 supports .NET 10 and Microsoft Testing Platform.
- (decision) AD-5 will use xUnit.net v3 for automated tests: core behavior is tested without console or filesystem access, JSON adapter behavior uses isolated temporary files, and end-to-end console automation is deferred.
- (decision) AD-6 will keep JSON DTOs in the storage adapter and map them through core validation before state replacement, preventing persistence shape from bypassing invariants or becoming the domain model.
- (decision) JSON uses UTF-8, camelCase properties, indented output, invariant decimal numbers, and ISO 8601 yyyy-MM-dd dates; one file contains a JSON array of expense DTOs.
- (constraint) Operational envelope is a single local process and a user-selected local file; there is no deployment, provider, server, telemetry, concurrency, or background operation in V1.
