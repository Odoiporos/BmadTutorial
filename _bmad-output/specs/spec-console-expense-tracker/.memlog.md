- (direction) Create a small implementation-ready spec from the completed beginner-friendly .NET project brainstorm; do not implement.
- (decision) Use slug console-expense-tracker and express distillation because the source establishes the product, learning goal, interface, persistence, and hard scope boundary.
- (capability) CAP-1: Add one validated expense so it becomes available to summaries and persistence.
- (capability) CAP-2: List recorded expenses with their core fields in a stable, readable order.
- (capability) CAP-3: Show the total amount across all recorded expenses.
- (capability) CAP-4: Show totals grouped by category.
- (capability) CAP-5: Save the current collection to local JSON or replace it by loading local JSON through one top-level storage command.
- (constraint) V1 is a local .NET console application with exactly five top-level commands and one expense entity.
- (constraint) Persistence is local JSON; no database, network service, authentication, deployment, or GUI is permitted.
- (constraint) Amounts use decimal values greater than zero; category is required; description is optional; date is required and defaults to the current local date when omitted.
- (constraint) Invalid input must be rejected without terminating the application or changing the current expense collection.
- (decision) Currency is represented by decimal amounts only; conversion, exchange rates, and mixed-currency handling are outside V1.
- (assumption) The fifth top-level command is named storage and exposes save and load actions, preserving the agreed five-command limit.
- (assumption) Loading valid JSON replaces the in-memory collection rather than merging it, preventing ambiguous duplicate behavior.
- (decision) Empty-state totals are zero, category summaries are ordered by category, and expense listings are ordered by date then entry order for deterministic output.
